# Техническое задание
## CRM-система управления продажами корпоративного обучения

**Версия:** 1.1  
**Дата:** июнь 2026  
**Изменения v1.1:** добавлен раздел 8 — интеграция через внешний API

---

## 1. Общее описание

### 1.1 Цель системы
Разработка веб-приложения для управления воронкой продаж корпоративного обучения. Система автоматизирует работу отдела продаж: ведение сделок, контроль задач, управление клиентской базой и формирование отчётности.

### 1.2 Целевая аудитория
- Менеджеры по продажам (основные пользователи)
- Руководитель отдела продаж
- Делопроизводитель
- Менеджер онбординга
- Прочие сотрудники (наблюдатели)

### 1.3 Платформа
Веб-приложение (SPA), адаптированное под десктоп. Стек: React + TypeScript, Python (backend), PostgreSQL.

## 3. Воронки продаж

### 3.1 Воронка «Академия продажи»

11 этапов:

> База → Новый лид → Недозвон → Взято в работу → Квалификация → Переговоры → Договор отправлен → Договор подписан → Счёт отправлен → **Успешно реализовано** / **Закрыто и нереализовано**

### 3.2 Воронка «Диагностическое тестирование»

8 этапов:

> Новый лид → Взято в работу → Отправлена форма → Отправлены доступы → Тесты прошли → Проведение встречи → **Переход в продажу** / **Закрыто и нереализовано**

## 4. Функциональные требования

### 4.1 Раздел «Воронка»

- Kanban-доска с колонками по этапам
- Перетаскивание сделок между этапами (drag & drop)
- Отображение суммы сделок в каждой колонке
- Поиск по названию, компании, тегам
- Расширенная фильтрация:
  - По компании, курсу, менеджеру, источнику, тегу, этапу
  - По наличию задач
  - По диапазонам: сумма, дата старта, дата окончания, дата счёта, дата оплаты, номер счёта
- Счётчик активных фильтров
- Создание новой сделки из любой колонки (по нажатию на заголовок)
- Переключение между воронками

### 4.2 Раздел «Сделки» (табличный вид)

- Таблица всех сделок с сортировкой по: названию, компании, сумме, этапу, менеджеру, кол-ву студентов
- Фильтрация: по этапу, приоритету задач, источнику, менеджеру, компании
- Индикатор приоритета задач (цветная точка)
- Визуальное выделение просроченных задач
- Итоговая сумма по отфильтрованным результатам
- Открытие карточки сделки по клику

### 4.3 Раздел «Задачи»

- Сводный список задач по всем сделкам
- Три вкладки: Активные, Просроченные, Выполненные
- Фильтрация по приоритету и сделке
- Отображение контекста: название сделки, компания; клик открывает сделку
- Жизненный цикл задачи:
  - Создание (текст, дедлайн, приоритет: высокий / средний / низкий)
  - Выполнение (чекбокс + поле с результатом)
  - Опция повтора задачи на новую дату
  - Отмена выполнения
  - Редактирование (текст, дата, приоритет)
- Сортировка: сначала просроченные, затем по дате

### 4.4 Карточка сделки (модальное окно)

**Вкладка «Информация»:**
- Редактирование всех полей сделки
- Быстрая смена этапа (с автозаписью в историю)
- Выбор курсов из каталога + создание нового курса прямо из формы
- Привязка компании из списка + быстрое создание новой
- Привязка контактов (только из выбранной компании) + быстрое создание нового контакта
- Управление тегами
- Кнопка удаления сделки с подтверждением

**Вкладка «История»:**
- Лента в хронологическом порядке
- Добавление комментария
- Добавление задачи
- Записи о переходах между этапами (автоматически)
- Управление задачами прямо из ленты

### 4.5 Раздел «Компании»

- Поиск по названию
- Добавление / редактирование компании
- Несколько юридических лиц на одну компанию
- Просмотр связанных контактов и сделок из карточки
- Удаление компании (с очисткой связей в сделках и контактах)

### 4.6 Раздел «Контакты»

- Поиск по имени
- Добавление / редактирование контакта
- Несколько телефонов и email с типами
- Флаг ЛПР (лицо, принимающее решение)
- Telegram
- Просмотр сделок, в которых участвует контакт
- Привязка к компании

### 4.7 Раздел «Менеджеры»

- Список менеджеров с количеством сделок
- Добавление, редактирование, удаление
- При удалении менеджера — очистка привязки в сделках

### 4.8 Импорт / Экспорт

- Экспорт всех сделок в CSV и XLSX
- XLSX: стилизованные заголовки, автоширина колонок
- Импорт сделок из CSV и XLSX
- При импорте: создание новых + обновление существующих (по ID)
- Отчёт об импорте: количество загруженных записей

## 6. Путь пользователя (менеджер по продажам)

### Сценарий 1: Первый рабочий день

1. Менеджер открывает систему в браузере, вводит логин и пароль
2. Видит **воронку «Академия продажи»** с колонками по этапам
3. Переходит в **«Менеджеры»** — убеждается, что его имя есть в списке
4. Переходит в **«Компании»** — смотрит клиентскую базу, добавляет свои компании
5. В карточке компании добавляет контакты с телефонами и флагом ЛПР

### Сценарий 2: Создание новой сделки

1. В разделе «Воронка» нажимает на заголовок нужного этапа — открывается форма
2. Вводит название, сумму, источник
3. Выбирает курсы из каталога
4. Выбирает компанию из списка (или создаёт новую прямо в форме)
5. Отмечает нужные контакты из компании
6. Нажимает **«Создать»** — сделка появляется в колонке
7. Открывает карточку → во вкладке «История» добавляет первый комментарий и ставит задачу: «Позвонить до пятницы», приоритет — высокий

### Сценарий 3: Ежедневная работа

1. Начинает день с раздела **«Задачи»** → вкладка «Просроченные»
2. Берёт задачу, звонит клиенту
3. Отмечает задачу выполненной, вписывает результат («Договорились на встречу 10.06»)
4. При необходимости ставит повторную задачу на новую дату
5. Открывает вкладку «Активные» → обрабатывает по приоритету

### Сценарий 4: Продвижение сделки

1. После успешных переговоров открывает карточку сделки
2. Во вкладке «Информация» меняет этап на «Договор отправлен»
3. Система автоматически фиксирует переход в истории
4. Заполняет номер счёта и дату выставления
5. Ставит задачу: «Проконтролировать оплату» с дедлайном

### Сценарий 5: Закрытие сделки

- **Успешное:** меняет этап на «Успешно реализовано», заполняет дату оплаты
- **Проигрыш:** меняет этап на «Закрыто и нереализовано», указывает причину отказа

### Сценарий 6: Работа с базой клиентов

1. Переходит в **«Компании»**, ищет по названию
2. Открывает компанию — видит всех контактов и все сделки с этим клиентом
3. Добавляет нового контакта, если появился новый представитель
4. Редактирует сегмент и регион для корректной сегментации

### Сценарий 7: Импорт данных (переход с другой системы)

1. Нажимает кнопку **«Импорт XLSX»**
2. Загружает файл с выгрузкой из старой CRM
3. Система создаёт/обновляет сделки, показывает: «Загружено 47 записей»
4. Проверяет результат в таблице сделок

### Сценарий 8: Передача дел

1. Открывает раздел **«Сделки»**, фильтрует по своему имени
2. Нажимает **«Экспорт XLSX»** — скачивает файл со всеми сделками
3. Передаёт руководителю для переназначения на нового менеджера

### 7.3 Описание ролей в деталях

#### Руководитель
Полный доступ без ограничений. Единственная роль, которая управляет пользователями, настраивает воронки и производит импорт данных. Видит все сделки всех менеджеров.

#### Менеджер
Основной пользователь системы. Ведёт полный цикл сделки от создания до закрытия, управляет задачами, работает с клиентской базой. Не может удалять компании, контакты и менеджеров — только Руководитель.

#### Делопроизводитель
Работает со сделками в части документооборота: заполняет номер счёта, даты выставления и оплаты, оставляет комментарии, ставит задачи. Может редактировать любые поля сделки, но не удалять их. Не управляет справочниками и не производит импорт.

#### Менеджер онбординга
Подключается к сделке после подписания договора. Видит все сделки и воронки, может ставить задачи и комментировать. Не редактирует финансовые поля (сумма, счёт, даты оплаты) и не создаёт новые сделки — работает только с уже существующими.

#### Прочие
Режим «только чтение». Могут просматривать воронку, таблицу сделок, базу компаний и контактов, историю — но не создают, не редактируют и не удаляют ничего. Подходит для смежных отделов, которым нужна видимость процесса без права вмешательства.

### 7.4 Требования к реализации авторизации

- Каждый пользователь имеет логин и пароль
- Сессия хранится в зашифрованном виде, автоматически истекает через 8 часов бездействия
- Роль назначается Руководителем через раздел «Пользователи»
- Ролевые ограничения применяются на уровне сервера (backend), не только в интерфейсе — скрытие кнопок в UI не является достаточной защитой
- При попытке выполнить недоступное действие сервер возвращает ошибку `403 Forbidden`
- Пользователь видит только те разделы и кнопки, к которым у него есть доступ — интерфейс адаптируется под роль

## 8. Интеграция через внешний API

### 8.1 Назначение

Возможность автоматического создания сделок в CRM из внешних источников: сайт, лендинг, форма обратной связи, сторонний сервис. Сделки создаются без участия менеджера — сразу попадают в нужную воронку на первый этап.

### 8.2 Принцип работы

Внешняя форма отправляет POST-запрос на выделенный API-эндпоинт CRM с данными в формате JSON. CRM создаёт сделку и при необходимости — компанию и контакт (если не существуют). Воронка определяется по полю `funnel` в теле запроса.

```
POST https://<crm-api-url>/intake
Content-Type: application/json
X-Api-Key: <ключ интеграции>
```

### 8.3 Структура входящего запроса

#### Воронка «Академия продажи» (`funnel: "academy"`)

```json
{
  "funnel": "academy",
  "title": "Обучение команды продаж — ООО Ромашка",
  "source": "Сайт",
  "company_name": "ООО Ромашка",
  "contact_name": "Иван Петров",
  "contact_phone": "+7 999 123-45-67",
  "contact_email": "ivan@romashka.ru",
  "contact_position": "Директор по персоналу",
  "course_names": ["Продажи B2B", "Переговоры"],
  "student_count": 15,
```

### 8.4 Поля запроса

| Поле | Тип | Обязательное | Описание |
|------|-----|:---:|----------|
| funnel | string | ✅ | Целевая воронка: `academy` или `diagnostics` |
| title | string | ✅ | Название сделки |
| source | string | ❌ | Источник (если не указан — «Сайт») |
| company_name | string | ❌ | Название компании (поиск по названию или создание новой) |
| contact_name | string | ❌ | ФИО контакта |
| contact_phone | string | ❌ | Телефон контакта |
| contact_email | string | ❌ | Email контакта |
| contact_position | string | ❌ | Должность контакта |
| course_names | string[] | ❌ | Названия курсов (поиск в каталоге или создание новых) |
| student_count | number | ❌ | Количество студентов |
| comment | string | ❌ | Текст первого комментария в истории сделки |

### 8.5 Логика обработки на сервере

1. Проверить `X-Api-Key` — если неверный, вернуть `401 Unauthorized`
2. Валидировать обязательные поля (`funnel`, `title`) — если отсутствуют, вернуть `400 Bad Request`
3. Определить начальный этап по воронке:
   - `academy` → этап **«Новый лид»**
   - `diagnostics` → этап **«Новый лид»**
4. Компания: найти по точному названию → если не найдена, создать новую
5. Контакт: найти по телефону или email → если не найден, создать новый и привязать к компании
6. Курсы: для каждого названия найти в каталоге → если не найден, создать новый
7. Создать сделку со всеми полученными данными
8. Если передан `comment` — добавить его первой записью в историю сделки (автор: «API»)
9. Вернуть `201 Created` с ID созданной сделки

### 8.7 Аутентификация

- Каждая интеграция получает уникальный API-ключ (`X-Api-Key`)
- Ключи генерируются Руководителем в разделе «Настройки → Интеграции»
- Можно создать несколько ключей (для разных форм/сайтов) и отозвать любой из них
- Каждый ключ можно ограничить по воронке: только `academy`, только `diagnostics`, или обе
- Все входящие запросы логируются: дата, источник IP, воронка, результат (успех / ошибка)

### 8.8 Раздел «Настройки → Интеграции» (UI)

- Список активных API-ключей с названием, датой создания, ограничением по воронке
- Кнопка «Создать ключ» — задать название и выбрать воронку
- Кнопка «Отозвать» — деактивировать ключ без удаления из истории
- Лог последних входящих запросов: дата, воронка, название сделки, статус
- Готовые примеры кода для подключения (HTML-форма, JavaScript fetch, Python requests)

### 8.9 Сценарий использования

1. Клиент заполняет форму на сайте: имя, телефон, компания, интересующий курс
2. Сайт отправляет POST-запрос на API CRM с ключом интеграции
3. CRM автоматически создаёт сделку в воронке «Академия продажи», этап «Новый лид»
4. Создаёт компанию и контакт (если новые)
5. Добавляет комментарий с текстом из формы
6. Менеджер в CRM видит новую карточку в воронке — берёт в работу
